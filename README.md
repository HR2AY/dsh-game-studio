# 沙盒游戏工坊（Game Studio）

一个本地 DSH Desktop 工作台：把工作区里的**静态网页小游戏**在 `localhost` 里跑起来，
一边看真实运行效果，一边让 AI 改代码。

- 服务对象：不会编程、有一点沙盒经验、想自己做游戏的青少年。
- 解决的问题：想法 → 可玩页面之间的那段路。不用配环境、不用开终端、不用懂构建。
- 一次任务：选文件夹 → 打开游戏 → 在 localhost 预览 → 对着预览说想改什么 → 存盘自动刷新。

## 一次任务的完整流程

1. **选游戏文件夹**：点「选择游戏文件夹」，用系统目录选择器选一个目录。
   工作台把「自己带 `index.html` 的文件夹」当作一个游戏；如果所选目录自己就有 `index.html`，
   就把整个目录当作一个游戏，否则往下找**两层**（`zip` 解压后多套一层文件夹是最常见的形态）。
   目录下的 **`.zip` 游戏包会被自动解压到缓存目录**并作为游戏列出（不修改原 zip）。
   选择记录写在 DSH 数据目录里，下次打开自动恢复。
2. **挑游戏**：卡片墙列出发现的所有游戏，卡片标题取自每个游戏的 `<title>`。
   游戏 id 是每次扫描生成的不含斜杠的短标识（`g0`、`g1`…），相对位置单独记录，
   所以中文名、多层文件夹都不会破坏预览地址。
3. **看它跑起来**：点开卡片后，工作台把自己的预览路由当 iframe 打开，
   地址形如 `http://127.0.0.1:<端口>/_dsh/game-studio/preview/<游戏>/`。
   顶栏「在浏览器打开」可以在系统浏览器里看同一个地址。
4. **边聊边改**：右侧是宿主提供的**原生会话**。还没有工作台会话时，
   点「为这个游戏开一个工作台会话」——工作台会把这个文件夹登记成 DSH 工作区，
   再由宿主创建会话；开场描述会显示出来，**由你自己按发送**。
5. **存盘即刷新**：AI（或你自己）改动游戏文件后，工作台监听到变化会向预览页推送
   一条 `reload` 事件，iframe 自动重新加载，不用手动刷新。

## 运行规则

- **不写入你的游戏目录**：工作台只读扫描与读取游戏文件；
  偏好与最近记录写在 `dsh.bundle.patch` 的 `config.root`（默认 `dshHomePath('game-studio')`）里。
- **预览只服务已登记的游戏**：预览只对刚在工作台里打开过的游戏目录生效，
  链接带一次性 token（Harness 重启即失效），`..` 之类的越界路径会被拒绝。
- **加载静态游戏**：只做静态文件服务，不执行构建、不装依赖、不跑 Node。
  需要网络、后端或打包步骤的游戏不在本工作台的能力范围内。
- **卸载不删数据**：卸载工作台只移除插件与入口，游戏文件和工作台记录都留在原处。

## 常见疑问

- **在「工作台管理」里点「查看安装说明」跳到 GitHub 404**：那是 Desktop 给"非市场安装"
  的兜底链接，指向本包的 `repository`（本地包没有真实仓库，填的是占位地址）。
  打开工作台请用左侧会话栏顶部的**模式切换器**选「沙盒游戏工坊」。
- **看到「预览授权已失效」**：预览 token 是 Harness 每次启动新生成的。
  工作台在打开面板与打开游戏时都会重新校验/获取 token；也可以点状态条上的
  **「刷新预览授权」** 立即重开预览。

## 包结构

```text
package.json                 # npm 与 DSH 插件声明（dsh.bundle.patch / dsh.client.*）
cordis.patch.yml             # 把服务端入口插入插件树（id: game-studio）
dsh/index.js                 # 服务端入口：游戏发现 + localhost 预览 + 变化推送
lib/client.js                # 已构建的客户端单文件入口（__ModuleLoader__.load）
scripts/check-workbench-package.mjs   # 包格式静态校验
scripts/test-server.mjs      # 服务端行为测试（不需要 Desktop）
```

本机接口都在自己的工作台前缀下：`/_dsh/game-studio/api`、`/_dsh/game-studio/preview`、
`/_dsh/game-studio/events`，不占用 Desktop 或 `/api`。

## 自测

```bash
node scripts/check-workbench-package.mjs   # 包格式与入口静态校验
node scripts/test-server.mjs               # 服务端行为测试（发现游戏、预览、越界拒绝）
node scripts/test-client.mjs               # 客户端行为测试（注册描述符、无会话/有游戏/已关联会话三种渲染）
```

界面与加载的验收（出现在「已安装的工作台」、左侧入口、真实预览）需要在 DSH Desktop 里手工完成。
